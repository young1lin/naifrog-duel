# 奶蛙对打 · Rust / Bevy 双人格斗

Rust / Bevy 2D 双人格斗原型。三种模式：**单机打人机**、**本地同屏双人**、**私人联机**（浏览器 + 服务器权威）。这不是完整的《街霸》/《恐龙快打》复刻。

[English](README.en.md) · [下载](https://github.com/young1lin/naifrog-duel/releases) · [Actions 构建](https://github.com/young1lin/naifrog-duel/actions/workflows/ci.yml) · [更新记录](CHANGELOG.md) · [参与开发](CONTRIBUTING.md)

项目代码及维护者提供的 AI 生成美术在可许可权利范围内采用 [MIT](LICENSE)，字体等第三方内容保留各自许可。维护者说明原图由其使用 ChatGPT 生成、原始图集由助手生成；具体来源标签与哈希记录见 [素材说明](assets/README.md) 和 [NOTICE](NOTICE.md)。公开候选包含游戏实际使用的原始图片和处理后图集，保持原来的 2D 效果。

## 版本与自动发布

Cargo.toml 的 package.version 是基础版本，Cargo.lock、CHANGELOG.md 和 v 版本标签必须一致。程序支持 --version；多人协议 PROTOCOL_VERSION 独立管理。

Actions 会实际编译 Windows 游戏 EXE、浏览器 WASM，以及 Linux/Windows 服务端，打包、校验后提供四个可下载产物。推送匹配版本标签后，Release 工作流在全部检查通过后创建**草稿 Release**，由维护者检查后手动发布。

使用 node scripts/version.mjs bump patch/minor/major 推进版本，补充更新记录并刷新发布清单后再提交、打标签。完整命令和兼容策略见 [发版说明](docs/RELEASING.md)。

## 运行（Windows 桌面）

需要 `rust-toolchain.toml` 固定的 Rust 1.98.1、Windows MSVC C++ 构建工具，以及 Node.js 22+。生成或检查素材前先在仓库根目录运行 `npm ci`（安装 [package.json](<package.json>) 里的 sharp，用来编解码 WebP）；静态服务器和各测试脚本不需要 npm 包。首次编译会下载并编译 Bevy，需耐心等待。

在项目根目录执行：

~~~powershell
.\scripts\run-game.ps1                # 启动后显示模式菜单
.\scripts\run-game.ps1 -Mode cpu      # 直接开始单机打人机（等同 -Ai）
.\scripts\run-game.ps1 -Mode local    # 直接开始本地同屏双人（等同 -Local）
.\scripts\run-game.ps1 -Mode demo     # CPU 对 CPU 演示（等同 -Demo），不是单机模式
.\scripts\run-game.ps1 -Server http://服务器IP:端口   # 菜单多出“3 私人联机”，连浏览器用的同一个服务器
.\scripts\run-game.ps1 -Lang en     # 英文界面（zh / en）；不写时跟随 NAIFROG_LANG 和系统语言
~~~

也可以直接执行 `cargo run --locked --bin naifrog-duel -- --mode cpu`（`menu` / `cpu` / `local` / `demo`），语言用 `--lang zh` / `--lang en`。

桌面菜单：↑/↓（或 W/S、手柄十字键）选择，Enter / Space / 手柄 A(South) / Start 确认；数字键 1、2、3 直接选；鼠标或触屏点按也可以。对局中 Esc 或手柄 Select 打开菜单并暂停（联机时不暂停），菜单里 Esc / 手柄 B(East) / “返回对局” 继续。单机与本地同屏对局在窗口失焦（如 Alt-Tab）时自动暂停；回到窗口后手动继续。初始菜单按 Esc 退出。F2 随时切换中 / 英文。

桌面版联机：用 `--server http://服务器IP:端口` 启动（也可以设环境变量 `NAIFROG_SERVER`，或用 `run-game.ps1 -Server`），菜单才有“3 私人联机”；可再加 `--name 名字` 带上昵称（规则同浏览器：字母、数字、空格、`_`、`-` 和常用汉字，最多 10 个字母或 6 个汉字宽；非法则退回 P1 / P2 并在控制台提示）。它连的是浏览器用的同一个 `naifrog-server`，房间互通：桌面建房、平板浏览器加入，反过来也可以。进入后在“服务口令”行用键盘输入服务口令（显示为 `*`）并按 Enter；登录后选“创建房间”，匹配码显示在顶部状态行；或在“加入房间”行输入对方的匹配码再按 Enter。对局中本机键盘和所有手柄都只控制你的席位；Esc / Select 打开菜单（不暂停），菜单里 B / Esc 回到对局，“离开房间”关闭房间，选 1 / 2 也会离开房间。桌面版只支持 `http://`，`https://` 服务器请用浏览器。口令只在内存里，不写入日志或文件。

## 中文 / English

网页和游戏画面里的文字始终是同一种语言：中文或英文。

- 浏览器：第一次打开时，浏览器的首选语言是中文（`zh` 开头）就用中文，否则用英文。菜单、房间、操作三个面板右上角都有“English / 中文”按钮，切换后网页和画面一起变（对局中切换也立即生效），选择记在本机 `localStorage`（键 `naifrog-lang-v1`）。网址加 `?lang=zh` 或 `?lang=en` 只决定这一次载入的语言，不改记住的选择。
- 桌面版：`--lang zh` / `--lang en`（`run-game.ps1 -Lang`）优先，写别的值会报错退出；没写时看环境变量 `NAIFROG_LANG`（如 `zh_CN.UTF-8`），没设才看系统语言；取到的语言既不是中文也不是英文时用英文。游戏中按 F2 切换，窗口标题一起变。
- 两种语言都保留 `P1` / `P2`、`VS` 与按键名（R、Esc、Start、A 等）。服务器下发的原因是英文协议字符串，网页按当前语言显示；联机消息格式没有变化。
- 画面上的汉字与中文标点由名字字体绘制（见“素材与开发”）；字体载入失败时汉字不显示，游戏照常运行。

## 模式与身份

颜色固定：**P1 永远是金色，P2 永远是蓝色**——血条、头顶标签、脚下圆环一致。标签跟着角色身份走，不跟左右位置走，两人换边后标签仍在原来的角色头上。

| 模式 | 你控制谁 | 标签 |
|---|---|---|
| 单机打人机 | 你是 P1（金色），CPU 是 P2（蓝色） | `P1 你` / `P2 电脑`（英文 `P1 YOU` / `P2 CPU`） |
| 本地同屏双人 | P1、P2 各自的设备 | `P1` / `P2` |
| 私人联机 | 服务器分配的席位；创建者通常是金色 P1，加入者通常是蓝色 P2 | `你` / `对手`（英文 `YOU` / `RIVAL`） |

血条上方还会显示双方名字（联机是创建 / 加入时填的昵称，其余模式是 `P1` / `P2`），名字旁边带着标签；头顶标签与脚下圆环仍跟着角色走，不跟左右位置走。

- 单机：两套键位、任意手柄、全部触屏摇杆与按钮都只控制你；CPU 不读取你的设备。
- 本地：P1 = A/D/W/S + F/G/H/T、1 号手柄、左半屏摇杆与按钮；P2 = 方向键 + J/K/L/I、2 号手柄、右半屏摇杆与按钮。
- 联机：本机所有键盘、手柄、触屏都只控制你自己的席位。
- 演示（`-Mode demo`）是两个 CPU 自动对打，仅用于截图和观察，不计入三种可玩模式。

CPU 只为自己的席位产生“按键输入”，与人类玩家走同一套输入与战斗规则，不改坐标、血量或胜负。它对你的动作有 12–20 帧（约 0.2–0.33 秒）的感知延迟，按短计划行动：接近、后退、防御、跳跃，在有效距离内才出轻拳 / 重拳 / 冲刺；远距离会丢奶泡弹，看到奶泡飞来会跳过或防御，跳起后有时会出肚皮压。目前只有一个固定难度。

## 操作

| 动作 | P1 / 单机 | P2 |
|---|---|---|
| 移动 | A / D | ← / → |
| 跳跃 | W | ↑ |
| 防御（按住） | S | ↓ |
| 轻拳 | F | J |
| 重拳 | G | K |
| 肚皮冲刺 | H | L |
| 奶泡弹 | T | I |
| 肚皮压（空中） | 跳起后按 F 或 G | 跳起后按 J 或 K |

单机时右手键位（方向键 + J/K/L/I）同样控制你。R / 手柄 Start / 画面上的“再来一局”按钮：重置整场比赛；整场结束（一方拿到两胜，或打满 5 局）的结果显示约 1 秒后，新按一次手柄 A 也能重开（松开时生效）。F1：判定框。F2（桌面版）：切换中 / 英文。

手柄：左摇杆 / 十字键移动，A(South) 跳，X(West) 轻拳，Y(North) 重拳，B(East) 冲刺，RB（右肩键）奶泡弹，LB / LT / RT 防御；跳起后按 X 或 Y 是肚皮压。Start 重开（整场结束的结果显示约 1 秒后 A 也可以），Select 暂停 / 继续。按键名称随手柄品牌而异。本地双人按连接顺序分配 1 号、2 号手柄；单机时任何手柄都控制你。网页的模式菜单和房间面板里：十字键 / 左摇杆移动，A 或 Start 确认，B 或 Select 返回；联机对局中按 Select 打开房间面板（默认停在“返回画面”）。

触屏：触屏设备（浏览器报告支持触摸）上，画面叠加半透明的虚拟摇杆和圆形按钮；电脑浏览器和桌面版不显示（触屏电脑在第一次触摸后才出现）。单机 / 联机：左半屏（状态栏以下）任意位置按下，摇杆就出现在手指下，左右拖动移动，上推跳跃，下拉防御，手指拖出圆圈时摇杆中心跟着手指走；右下角四个圆形按钮排成菱形：左“轻拳”、上“重拳”、右“冲刺”（对应手柄 X / Y / B），下“奶泡”（奶泡弹，对应手柄 RB），自己的奶泡还在场上时“奶泡”变灰；英文界面是 LIGHT / HEAVY / DASH / SHOT。没有跳跃按钮：摇杆上推就是跳，斜上推是向前 / 向后跳（躲奶泡用向前跳）。跳起后按“轻拳”或“重拳”是肚皮压。本地双人：左半屏归 P1、右半屏归 P2，各有一个摇杆和一组缩小的按钮。支持多指同时操作，每根手指按下时归属固定（某个摇杆或按钮），不会滑到另一位玩家；正常抬手保留短按，取消触摸则清理该手指的输入。控件出现后，鼠标左键可以像一根手指一样调试。

## 平板 / 浏览器（离线：单机与本地）

~~~powershell
.\scripts\build-web.ps1 -Release
node scripts/serve-web.mjs --host 0.0.0.0 --port 18080
~~~

本机打开 <http://127.0.0.1:18080>，先在网页菜单中选择“单机打人机”或“本地同屏双人”；数字键 1 / 2、点按、触屏均可。Esc 或右上“菜单”暂停并返回菜单；切到后台标签页会自动暂停。平板与电脑处于同一局域网时，使用服务器打印的 Tablet LAN 地址，允许 Windows 防火墙的专用网络访问。不要开放公网端口。

`serve-web.mjs` 只是离线 / 局域网调试服务器：没有登录、没有联机，菜单里的“私人联机”会显示为不可用。它只公开页面、生成的 WASM 与处理后的贴图，不公开原始素材或项目文件。

推荐横屏、支持 WebGL2 的近期浏览器。“操作”按钮提供中 / 英文操作说明，“全屏”受浏览器权限限制。局域网或公网 IP 上的 `http://` 页面可以触屏和键盘游玩，但部分浏览器只在 HTTPS 页面提供手柄 API；桌面 localhost 不受此限制。

[网页构建脚本](<scripts/build-web.ps1>)自动匹配 [Cargo 锁文件](<Cargo.lock>)中的 wasm-bindgen 版本。不加 `-Release` 时生成体积大得多的调试构建；`-Release` 构建约 21.5 MiB（另生成约 5.7 MiB 的 gzip 副本），整程序 LTO 编译更慢。网页输出不纳入源码版本管理。

## 私人联机

联机只能通过生产服务器 `naifrog-server` 使用（部署见 [DEPLOY.md](<DEPLOY.md>)）。下面是浏览器的步骤；桌面版见上文“桌面版联机”，房间与浏览器互通：

1. 打开服务器地址，输入服务口令登录（口令由服务器管理员通过安全渠道单独告知，不出现在网址里）。有域名时是 `https://域名`；没有域名时可以是 `http://服务器IP:端口`，但这样口令和对局数据不加密，登录页会提示（见 DEPLOY.md“没有域名”）。
2. 在模式菜单选“私人联机”，可先在“你的名字”里填一个昵称（字母、数字、空格、`_`、`-` 和《通用规范汉字表》的 8105 个常用汉字；最多 10 个字母或 6 个汉字宽，可以混用，例如“奶蛙Pro123”；全角标点、表情等显示不了的字符输入时就会提示，非法或留空就是 P1 / P2），再点“创建房间”，把 8 位匹配码发给朋友；朋友登录后同样可填昵称，输入匹配码加入。名字只随创建 / 加入消息发给服务器、只出现在快照里，不用于鉴权也不写日志；浏览器把它记在本机 `localStorage`（键 `naifrog-name-v1`），下次自动填好——那里永远不存口令。
3. 两边都到齐后由服务器开始对局：先显示约 2 秒的开场对阵画面（双方名字 + `VS`），再进入“第一局”（`ROUND 1`）倒数。名字会一直显示在血条上方（旁边是“你 / 对手 / 电脑”，英文 `YOU` / `RIVAL` / `CPU`）。重开需要双方各按一次 R / Start / “再来一局”（或整场结束的结果显示约 1 秒后的手柄 A）。
4. 在模式菜单改选单机或本地会离开房间，对方会看到“房间已关闭”。一个席位同一时间只在一个标签页有效：在另一个标签页接管后，旧页面会断开并提示，刷新旧页面可以取回。

服务器以 60 Hz 运行同一套战斗代码，20 Hz 下发快照，客户端约 50 ms 插值显示。客户端只上传按键，不上传位置、血量或胜负。**没有客户端预测或回滚**，手感取决于双方到服务器的延迟。匹配码只用于找到房间，不是访问凭据。房间不按固定时间过期：只要有一方连着（服务器每 10 秒发一次 WebSocket ping，10 秒内没有回应就算断线），房间就一直保留，等人多久都可以；最长 12 小时，与登录会话一样。断线时对局暂停，席位保留 5 分钟（够平板切出去再回来、重新载入页面），刷新页面会尝试恢复。断线一方的画面会显示重试次数与“立即重试”按钮；等的一方画面显示对方席位的保留倒计时（“对手已断线，席位保留 4:59”，英文 `RIVAL DISCONNECTED 4:59`）。对局中途断线后恢复的回合先播 3-2-1 倒计时（各 1 秒，共 3 秒）：期间与回合开场相同——输入无效、99 秒计时与所有角色冻结，倒计时结束才继续；开局与等人的房间不播倒计时，结果已出的回合恢复后直接显示结果。

本机回环上的双浏览器联机验收（PC 键盘建房、平板尺寸触屏加入）与安全验收已经通过；没有域名的 `http://` 方式也在本机用非回环地址模拟，跑通了同一套联机验收。结果见 [测试记录](<TESTING.md>)。桌面版联机客户端：自动测试让两个桌面客户端连本机真实服务器，跑通登录、建房、加入、移动同步、重开投票、离开；同一客户端代码也对一台已部署的 `http://IP:端口` 服务器跑通了登录、建房、加入、移动、离开（两个客户端在同一台电脑上）。**尚未验证**：桌面菜单里的键盘输入与真手柄操作、电脑与平板跨设备的真实对局、真实公网延迟下的手感、HTTPS 部署、真平板、真手柄；这些需要按测试记录和部署文档里的清单人工完成。

## 已实现与规则

- 12 套角色动画：待机、新版走路、跳跃、防御、受击、倒地、起身、轻拳、新版重拳、肚皮冲刺、奶泡弹、肚皮压。**奶泡弹和肚皮压目前是占位图**（素材脚本分别复制轻拳、冲刺的图集，资产清单里标着 `placeholder`），正式原画还没有。背景、程序阴影、8 帧命中特效；奶泡的飞行 / 破裂 8 帧由素材脚本程序生成。
- 60 Hz 整数定点战斗；渲染插值不参与判定；双方从同一份本帧开始位置计算转向，跳跃换边时交换席位不会改变格挡结果；同帧互相命中、双 KO 平局；前方防御削血：扣原伤害的 1/4（向上取整：轻拳 2、重拳 4、冲刺 4、奶泡 3、肚皮压 3），削血也能 KO；倒地/起身无敌；99 秒按血量决胜；KO 与重开。
- 顿帧（hit-stop）：未被防御的命中让全场定格 4 帧——双方、飞行中的奶泡与 99 秒计时器一起暂停；被防御（削血）的命中不触发。连续命中时定格取最长、不叠加；顿帧期间按下的攻击 / 跳跃边沿直接丢弃，不会在顿帧结束后补发。
- 连击计数：打进同一段受击硬直的连续命中会累计（受击方恢复行动即清零，防御削血不计）。两次起，攻击方血条下方显示“N 连击”（英文 `N HITS`）。轻拳总长 22 帧大于受击硬直 18 帧，地面不能轻拳连轻拳——计数主要来自把对手打上天的空中追打，不代表可以无限连。
- 每局（含重开后）以 90 帧（1.5 秒）开场倒数开始：画面居中先显示“第一局”再显示“开打！”（英文 `ROUND 1` / `FIGHT!`），期间输入无效、99 秒计时器不走；倒数结束的那一帧才接受输入并开始计时。**第一局（含整场重开后）在倒数前多 120 帧（2 秒）开场对阵画面**：居中显示双方名字与 `VS`（联机用创建 / 加入时填的昵称，单机 / 本地是 P1 / P2），同样输入无效、计时不走；第二局起只有 1.5 秒倒数。结算时居中横幅显示“击倒！”/“时间到”/“平局”（英文 `K.O.` / `TIME OVER` / `DRAW`），获胜方满血则显示“完胜！”（`PERFECT!`）。单机、本地、联机（服务器跑同一套模拟）规则一致。
- 三局两胜：每局重置血量、位置、奶泡与 99 秒计时，先赢两局的一方获胜；平局（双 KO 或时间到同血量）不点亮任何胜局标记。结果展示约 2 秒后自动进入下一局（横幅“第二局”，能分出胜负的一局显示“决胜局”；英文 `ROUND 2` / `FINAL ROUND`）；打满 5 局仍无人两胜时，多胜者获胜，否则整场平局。血条下方每边两颗胜局标记，赢一局点亮一颗，标记下方是连击计数；血条外侧是双方共用的头像（待机第一帧裁切生成），框色随座位金 / 蓝。血量低于 25 时血条边框红色脉动（填充色保持座位纯色，像素探测的血量读数不受影响）；最后 10 秒计时器数字变红。R / 手柄 Start / “再来一局”与联机双票重开重置的是**整场比赛**。
- 轻拳：8/4/10 帧，伤害 8。重拳：14/6/18 帧，伤害 16、击倒。冲刺：12/10/20 帧，伤害 14、击倒。奶泡弹：14/1/24 帧，第 14 帧在身前 90 单位生成奶泡，伤害 10、不击倒。肚皮压：5/14 帧，伤害 10、不击倒。三个数依次为启动/有效/收招。
- 奶泡：每帧飞 8 单位，离地 50–110 单位高；每人场上最多一颗（有一颗时再按无效）；两颗相撞互相抵消；飞出场地边缘消失；穿过倒地 / 起身无敌的对手；站在地面面向奶泡按住防御可以挡（削血 3）。站着不动的对手仍会被打中（扣 10），太早起跳也会被打中。
- 跳跃：空中缩腿，受击框变窄（±50，原来 ±70）、离地 40 单位以上才算，所以算准时机能跳过奶泡。起跳速度 19 单位/tick、重力 0.85/tick，滞空 43 帧（约 0.72 秒）、顶点约 203 单位。从开场距离对方出奶泡起算，原地跳有 14 帧的起跳时机（第 34–47 帧），向前跳有 35 帧（第 11–45 帧）（单元测试实测）。代价是轻 / 重拳只能打到刚起跳或快落地的对手。
- 肚皮压：空中按轻拳或重拳，每次跳跃只能一次；保持起跳时的水平速度继续下落，落地立即可以行动；可被防御。
- 同一次攻击最多命中/被防御一次；按住攻击或跳跃不会连发。收招、受击、空中期间不缓存攻击；空中只能出肚皮压。
- 输入优先级：防御 > 冲刺 > 重拳 > 轻拳 > 奶泡弹 > 跳跃 > 移动。左右同时按住互相抵消。每个固定 tick 只消费一次按下边沿。
- 重开时清理待处理边沿，已按住的攻击/跳跃必须先松开再按；失焦、触摸取消、手柄断连会清理对应输入。同一玩家同时用两只手柄时，拔掉其中一只不会让另一只仍按住的键再次触发。整场结束后的约 1 秒内按下的手柄 A（含一直按住的）不会重开，免得连按跳跃跳过结果；之后新按下的 A 在松开时才重开，新比赛不会多出一次跳跃。还没打满整场的局间结果里手柄 A 不触发重开，局间自动进入下一局。
- 切换模式、暂停、联机进出时会清空按住的键、触摸归属与残留按下边沿；联机模式下本地不模拟、不演示，也不能单方面重开。

## 素材与开发

[资产清单](<assets/processed/game-assets.json>)记录所有来源、SHA256、映射、基线与统一比例。原始素材不改写；先提取连通角色，再归一化至 512×512 的 4×2 图集，跨原始格线的拳头/躺姿不会被格线截断。轻拳第 5 格使用第 4 格替代，避免中途换手。新版走路循环仍需进一步打磨。游戏贴图（图集、特效、阴影、头像、背景）输出为无损 WebP：像素与原先的 PNG 逐一相同，体积不到一半。

名字里的汉字由 [名字字体](<assets/processed/name_font.otf>) 绘制：Noto Sans SC Medium（SIL OFL 1.1，[许可证](<assets/processed/name_font-OFL.txt>)随附）裁剪到可打印 ASCII、8105 个常用汉字与 171 个中文标点（界面上的中文文字也用它），约 1.8 MB，浏览器载入一次后缓存。[名字字体脚本](<scripts/prepare-name-font.mjs>)按固定地址与 SHA256 下载字体和 Unihan 数据（缓存在 `target/name-font-cache/`；需要代理时加环境变量 `NODE_USE_ENV_PROXY=1`），同时写出 [名字可用汉字表](<src/name_han.txt>)；服务器、桌面版和网页的名字校验都用这张表，字体缺失时汉字不显示，但游戏照常运行。

~~~powershell
npm ci
node scripts/prepare-game-assets.mjs
node scripts/prepare-game-assets.mjs --previews   # 可选：预览 GIF 写入 artifacts/previews/，不发布
node scripts/prepare-name-font.mjs   # 只在更换名字字体或字表时运行，需要联网
node scripts/check-assets.mjs
cargo test --locked --no-default-features --lib
cargo test --locked --no-default-features --features server --lib
cargo test --locked --no-default-features --features "server client" --lib   # 含桌面联机客户端对真实服务器的测试
node --test scripts/server.test.mjs
node --test scripts/network.test.mjs   # 重连探测的异步返回与换连接回归
cargo fmt --all --check
cargo clippy --all-targets --all-features -- -D warnings
cargo run --bin naifrog-duel -- --smoke artifacts/smoke.png --mode cpu
~~~

[纯战斗模块](<src/combat.rs>)、[统一输入模块](<src/controls.rs>)、[CPU 对手](<src/ai.rs>)、[模式与按钮布局](<src/ui.rs>)无需 Bevy 即可测试；[游戏入口](<src/main.rs>)负责渲染、设备适配和界面。[完整素材流水线](<scripts/prepare-game-assets.mjs>)用 [PNG/GIF 编解码器](<scripts/sprite-codec.mjs>)读取原图，由 [WebP 编码模块](<scripts/webp-codec.mjs>)（sharp）写出运行贴图。默认不生成预览；加 `--previews` 时将 GIF 写到 `artifacts/previews/`。`assets/processed/` 仅存放游戏贴图、清单和字体，校验脚本会拒绝多余文件。角色保留原始 2D 动画；历史试验、旧预览和审查产物留在本地归档，不入库、不发布。

## 当前限制

仅一个场景、同角色镜像两人，靠金 / 蓝标识区分。没有音效、连招、难度选择或专用胜利原画；奶泡弹和肚皮压的角色动作是占位图（轻拳、冲刺的图），等正式原画；胜者使用待机动画与获胜横幅。网页菜单与房间面板支持鼠标、键盘、触屏与手柄；登录口令只能用键盘输入。来源素材仍有少量边缘噪点、体型/动作细节差异；这是可玩的开发原型，不是最终美术。多键键盘的硬件冲突可能影响双人操作，建议有线手柄或支持足够同时按键的键盘。

详细验收记录见 [测试记录](<TESTING.md>)，部署见 [DEPLOY.md](<DEPLOY.md>)。
